# 数字员工运营数据埋点对接方案

## 一、实施阶段

| 阶段 | 接入方式 | 数据类型 | 上报频率 | 责任方 |
| --- | --- | --- | --- | --- |
| **过渡方案（6月底）** | Excel提报 → 指定人统一导入 | 日汇总统计 | 每天 | 各负责人提报，于思淼导入 |
| **长期方案（后续）** | API接口同步 | 执行明细 | 实时/准实时 | 业务方调用接口推送 |

---

## 二、过渡方案    （6月底实施）

### 2.1 Excel提报流程

#### 2.1.1 提报方式

*   **提报人**：各数字员工负责人
    
*   **接收人**：于思淼
    
*   **提报频率**：每天
    
*   **提报内容**：按统一模板填写的Excel文件
    
*   **填报模板**：
    

[请至钉钉文档查看附件《数字员工运营数据日汇总数据填报模版.xlsx》。](https://alidocs.dingtalk.com/i/nodes/pYLaezmVNe0KnN5ZHPql0vXGWrMqPxX6?cid=75312906801&corpId=ding5bb1eba46e6a17d94ac5d6980864d335&doc_type=wiki_doc&iframeQuery=anchorId%3DX02mquit6blwlpvx8f8ue&utm_medium=im_card&utm_scene=person_space&utm_source=im)

#### 2.1.2 数据处理流程

```plaintext
各负责人每日填写Excel → 发送给于思淼 → 于思淼统一导入后台数据库

```

#### 2.1.3 字段说明

| 字段 | 类型 | 含义 | 计算规则/说明 |
| --- | --- | --- | --- |
| `id` | BIGINT | 主键ID | 自增主键 |
| `employee_code` | VARCHAR(64) | 数字员工code | 格式：DE2026001 |
| `employee_name` | VARCHAR(255) | 数字员工名称 | — |
| `use_count` | BIGINT | 当日使用次数 | 去重后的调用条数 |
| `user_count` | BIGINT | 当日使用人数 | 去重后的使用人账号数 |
| `success_count` | BIGINT | 当日成功次数 | 调用状态为success的条数 |
| `abnormal_count` | BIGINT | 当日异常次数 | 调用状态非success的条数 |
| `input_token` | BIGINT | 当日输入Token | — |
| `output_token` | BIGINT | 当日输出Token | — |
| `total_token` | BIGINT | 当日Token消耗 | input\_token + output\_token |
| `total_duration_sec` | BIGINT | 当日运行时长 | 所有调用耗时之和，单位秒 |
| `normal_duration_sec` | BIGINT | 当日正常运行时长 | 成功调用耗时之和，单位秒 |
| `save_man_days_per_call` | DECIMAL(18,6) | 单次任务节省人天 | 数字员工上架时填报，平台按此计算效益 |
| `benefit_man_days` | DECIMAL(18,6) | 当日效益人天 | save\_man\_days\_per\_call × use\_count |
| `cost_amount` | DECIMAL(18,6) | 成本金额 | — |
| `currency` | VARCHAR(16) | 币种 | 默认CNY |
| `created_time` | DATETIME | 数据生成时间 | 默认当前时间 |
| `dt` | DATE | 分区日期 | 格式yyyy-MM-dd |

    *   格式：`DE` + 年份 + 三位序号
        
    *   示例：`DE2026001`、`DE2026002`

## 三、后续方案（接口模式）

### 数字员工调用流水明细写入接口文档

### 接口地址，无需鉴权

```text
POST /msService/public/digital-employee-service/api/call-details-save

```

### 请求头

| 请求头 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- |
| `Content-Type` | 是 | `application/json` | 请求体格式 |

### 请求参数

| 字段 | 类型 | 必填 | 示例 | 说明 |
| --- | --- | --- | --- | --- |
| `requestId` | string | 否 | `REQ-20260626-000001` | 调用方生成的请求 ID，用于链路追踪和幂等；应要求改成非必填 |
| `employeeCode` | string | 是 | `DE-2026-0001` | 数字员工编号，必须已存在 |
| `employeeName` | string | 否 | `合同审查员工` | 数字员工名称快照；不传时服务端按员工主表补齐 |
| `userId` | string | 否 | zhangsan | 使用人账号 ID，域账号口径；应要求改成非必填 |
| `userName` | string | 否 | `张三` | 使用人姓名 |
| `userDeptId` | string | 否 | `D001` | 使用人部门 code；应要求改成非必填 |
| `userDeptName` | string | 否 | `法务部` | 使用人部门名称 |
| `callStartTime` | string | 否 | `2026-06-26T10:00:00` | 调用开始时间，建议使用 ISO-8601 本地时间格式 |
| `callEndTime` | string | 否 | `2026-06-26T10:00:08` | 调用结束时间，建议使用 ISO-8601 本地时间格式 |
| `durationSeconds` | number | 否 | `8` | 调用耗时，单位秒； |
| `inputToken` | number | 否 | `120` | 输入 Token 数 |
| `outputToken` | number | 否 | `80` | 输出 Token 数 |
| `totalToken` | number | 否 | `200` | Token 总数；不传时服务端按 `inputToken + outputToken` 计算 |
| `callStatus` | string | 否 | `success` | 调用状态，只允许 `success`、`fail`、`timeout`、`cancel`；服务端会 trim 后转小写 |
| `errorCode` | string | 否 | `MODEL_TIMEOUT` | 异常编码 |
| `errorMessage` | string | 否 | `模型调用超时` | 异常信息 |
| `modelName` | string | 否 | `gpt-4.1` | 模型名称 |
| `modelProvider` | string | 否 | `openai` | 模型供应商 |
| `sourceSystem` | string | 否 | `contract-system` | 来源系统 |
| `extJson` | string | 否 | `{"scene":"contract_review"}` | 扩展 JSON 字符串，服务端透传保存 |

调用方不需要传 `id` 和 `dt`：

*   `id` 由数据库生成。
    
*   `dt` 由服务端生成；优先取 `callStartTime` 所在自然日，没有 `callStartTime` 时取服务端当前日期。
    

### 请求示例

```json
{
  "requestId": "REQ-20260626-000001",
  "employeeCode": "DE-2026-0001",
  "employeeName": "合同审查员工",
  "userId": "zhangsan",
  "userName": "张三",
  "userDeptId": "D001",
  "userDeptName": "法务部",
  "callStartTime": "2026-06-26T10:00:00",
  "callEndTime": "2026-06-26T10:00:08",
  "durationSeconds": 8,
  "inputToken": 120,
  "outputToken": 80,
  "totalToken": 200,
  "callStatus": "success",
  "errorCode": null,
  "errorMessage": null,
  "modelName": "gpt-4.1",
  "modelProvider": "openai",
  "sourceSystem": "contract-system",
  "extJson": "{\"scene\":\"contract_review\"}"
}

```

### 响应参数

接口统一返回 `BaseResult<Boolean>`。

| 字段 | 类型 | 示例 | 说明 |
| --- | --- | --- | --- |
| `code` | number | `1` | 业务状态码，`1` 表示成功，`0` 表示失败，`400` 表示参数校验错误 |
| `msg` | string | `操作成功!` | 返回消息 |
| `data` | boolean | `true` | 是否写入或幂等成功 |

成功响应：

```json
{
  "code": 1,
  "msg": "操作成功!",
  "data": true
}

```

失败响应示例：

```json
{
  "code": 0,
  "msg": "数字员工不存在",
  "data": null
}

```

### 业务规则

*   `employeeCode` 必填。
    
*   `employeeCode` 必须能在数字员工主表中查到。
    
*   同一 `requestId + employeeCode` 重复上报时按幂等成功处理，直接返回 `true`，不会覆盖历史记录。
    
*   `employeeName` 为空时，服务端使用数字员工主表名称补齐。
    
*   `durationSeconds`、`inputToken`、`outputToken` 为空时按 `0` 保存。
    
*   `totalToken` 为空时按 `inputToken + outputToken` 计算。
    
*   `extJson` 不解析内部字段，仅透传保存。
    

### 常见错误

| 场景 | 返回消息 |
| --- | --- |
| 请求体为空 | `调用流水不能为空` |
| `employeeCode` 为空 | `员工编号不能为空` |
| 数字员工不存在 | `数字员工不存在` |
| 请求体 JSON 格式错误 | `请求体格式错误` |
| 数据库异常 | `数据库访问异常` |
