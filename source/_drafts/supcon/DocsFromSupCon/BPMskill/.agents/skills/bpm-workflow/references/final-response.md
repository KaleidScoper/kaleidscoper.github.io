# BPM 最终答复要求

## 8. 最终答复要求

最终答复按操作者的执行顺序写，直接给出已知入口、动作和结果；同一事实只写一次，只列影响修改或验证结论的未确认事项。按任务阶段和需求类型选用以下内容：

1. **需求类型与环境计划**：说明本次是完整开发、BUG 修复、混合需求，还是独立执行单据、仅同步保存等阶段任务；只说明本次涉及的环境、步骤和完成结果，不自动补齐整个开发交付链。
2. **项目归属结论**：当前项目是否与需求匹配，以及判断证据。
3. **现状与根因**：相关代码入口、调用链、工作流定义与运行上下文、当前行为和需求差距；BUG 修复还应包括仿真环境的修复前复现证据。
4. **修改清单**：代码或视图修改应逐文件列出行号、稳定锚点、删除／替换／新增内容及理由；工作流修改应列出模块、实体、工作流名称或 `processKey`、节点／流转线等稳定锚点、当前配置、目标配置和关联视图／脚本／人员分配。
5. **影响与边界**：说明改动生效范围和已知风险；涉及工作流时，区分新发起实例与已在途实例。
6. **现场操作**：低代码需求说明自定义区同步、后端代码“保存”、视图设计器或视图代码编辑器的“保存并发布”、工作流设计器操作，以及获准执行的模块普通发布，分别报告保存结果和实际生效范围。Agent 已执行的步骤报告实际结果，需人工执行的步骤给出修改单。新建自建文件说明本地文件、开发环境目标路径、整文件上传方式及生效步骤。
7. **入库与构建**：说明如何只同步本次变更、创建临时分支和合并请求，并完成 Jenkins 构建。
8. **部署与验证**：说明开发在测试环境的冒烟、测试团队在测试环境的正式测试、测试团队在仿真环境的回归，以及所需请求数据、接口日志、页面结果和截图；工作流变更还应覆盖实际流程版本、受影响节点、流转条件、办理人、节点页面、流程脚本和结束／生效行为。
9. **未确认事项**：只列会影响修改、发布或验证结论的待核实内容。
10. **提示词系统冲突与更新建议**：如果本次任务发现用户说明或提示词体系与源码、现场配置、日志、接口响应、页面行为或其他关键事实冲突，应列出冲突内容、采用的证据、对当前结论的影响，以及建议更新的规则文件和具体位置；没有此类冲突时无需机械输出本项。
