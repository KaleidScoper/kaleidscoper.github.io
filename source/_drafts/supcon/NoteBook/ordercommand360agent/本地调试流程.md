# ordercommand360agent 本地调试流程

> 适用场景：每次完成开发改动后，启动三个本地服务，在浏览器查看效果并做基本验证。

## 1. 前置检查

项目由三个 Node 服务组成：

| 服务 | 目录 | 端口 | 作用 |
|---|---|---:|---|
| 后端 API | `backend` | 3001 | 业务数据、登录、权限、订单/任务 API、`/ws/chat` |
| Agent 服务 | `agent-service` | 3002 | Skill、模型、MCP、定时任务、Agent WebSocket `/ws/agent` |
| 前端 | `frontend` | 5173 | React + Vite 页面 |

确认 Node 可用：

```powershell
node --version
npm.cmd --version
```

如果 `npm --version` 在 PowerShell 中报 `npm.ps1 cannot be loaded`，用 `npm.cmd` 替代。

## 2. 首次或依赖变化后安装依赖

只在首次拉仓库、删除过 `node_modules`、或 `package-lock.json/package.json` 有变化时执行。

```powershell
cd D:\CodexWorkSpace\ordercommand360agent\backend
npm.cmd install

cd D:\CodexWorkSpace\ordercommand360agent\agent-service
npm.cmd install

cd D:\CodexWorkSpace\ordercommand360agent\frontend
npm.cmd install
```

## 3. 确认本地配置文件

这些文件通常是本地私有配置，不进入 Git：

```text
backend\.env
frontend\.env
agent-service\.claw\.env
agent-service\.claw\llm.config.json
agent-service\.claw\skills\...
```

基础端口配置：

```text
backend: PORT=3001
agent-service: PORT=3002
frontend: VITE_API_BASE_URL=http://localhost:3001/api
frontend: VITE_AGENT_BASE_URL=http://localhost:3002
```

如果需要真实 AI 回复，把大模型 Key 填到：

```text
D:\CodexWorkSpace\ordercommand360agent\agent-service\.claw\llm.config.json
```

对应字段：

```json
"apiKey": "你的 Key"
```

## 4. 启动三个服务

建议开三个独立 PowerShell 终端，便于看日志和停止服务。

终端 1：后端 API

```powershell
cd D:\CodexWorkSpace\ordercommand360agent\backend
npm.cmd run dev
```

终端 2：Agent 服务

```powershell
cd D:\CodexWorkSpace\ordercommand360agent\agent-service
npm.cmd run dev
```

终端 3：前端

```powershell
cd D:\CodexWorkSpace\ordercommand360agent\frontend
npm.cmd run dev
```

浏览器访问：

```text
http://localhost:5173/
```

默认登录：

```text
admin / 123456
```

## 5. 启动后健康检查

后端：

```powershell
Invoke-RestMethod http://localhost:3001/health
```

Agent：

```powershell
Invoke-RestMethod http://localhost:3002/health
```

前端：

```powershell
Invoke-WebRequest http://localhost:5173/
```

期望结果：

- 后端返回 `status: ok`
- Agent 返回 `status: ok`
- 前端返回 HTTP 200

## 6. 每次开发后的基本验证顺序

1. 看终端是否有编译错误或运行时异常。
2. 刷新 `http://localhost:5173/`。
3. 使用 `admin / 123456` 登录。
4. 验证本次改动相关页面。
5. 打开浏览器开发者工具：
   - Console：看前端异常。
   - Network：看 API 请求是否 200/401/500。
6. 如涉及 Agent，确认 `http://localhost:3002/health` 正常，并检查 Skill/模型配置。
7. 如涉及后端数据，确认 `backend/data/analysis.db` 是否为预期数据库。

## 7. 常见问题

### npm 在 PowerShell 中无法运行

如果出现：

```text
npm.ps1 cannot be loaded because running scripts is disabled on this system
```

使用：

```powershell
npm.cmd install
npm.cmd run dev
npm.cmd run build
```

原因是 PowerShell 执行策略禁止运行 npm 的 `.ps1` 包装脚本，但 `npm.cmd` 是 Windows 命令脚本，不受该策略影响。

### 端口被占用

查看占用：

```powershell
netstat -ano | findstr :3001
netstat -ano | findstr :3002
netstat -ano | findstr :5173
```

结束对应进程：

```powershell
taskkill /PID <进程号> /F
```

### 构建失败但开发服务能跑

当前仓库存在 TypeScript 构建错误，`npm.cmd run build` 不一定通过。日常看页面效果优先使用 `npm.cmd run dev`。如果准备发版或提交质量修复，再集中处理构建错误。

## 8. 停止服务

在对应终端按：

```text
Ctrl + C
```

如果是后台启动的进程，可用任务管理器或 `taskkill` 停止对应 node 进程。
