请先阅读 `docs\zyz\project-handover-notes.md`，充分了解项目的业务背景、目标用户、页面结构、技术栈及现有界面。随后检查 `.agents\skills` 目录下提供的前端设计相关参考，了解可供采用的设计原则、设计语言和实现方式。我们对项目目前的视觉效果评审意见位于 `docs\zyz\design-rebuild\visual-design-review.md`，基于以上这些参考重新设计项目的视觉语言。你的目标不是刻意做出与现有界面完全不同的新风格，而是建立一套更成熟、更一致、更符合项目定位的视觉系统。可自行决定采用 `.agents\skills` 中哪些设计参考，并说明理由。请在 `docs\zyz\design-rebuild\demo` 下输出一个或多个 HTML 单文件视觉原型。

要求如下：

* 每个 HTML 必须为完整、自包含的单文件，可直接在浏览器打开；
* 可以内置 CSS、JavaScript、SVG、示例图片、模拟数据等内容；
* 不需要连接真实后端，也无需实现真实业务逻辑；
* 可以使用假数据、静态交互、占位内容，仅用于展示视觉效果；
* 优先覆盖项目最具代表性的核心页面，而不是所有页面。

如果你认为存在多种合理设计方向，可以输出多个方案，例如不同的设计语言、品牌定位或视觉策略。但不要为了增加方案数量而刻意制造差异；只有当多种方案都具有合理性时才分别输出。

每个方案都应体现完整而统一的视觉系统，包括但不限于：

* 色彩体系；
* Typography；
* 间距体系；
* 页面布局；
* 导航设计；
* 卡片、按钮、输入框、表格等基础组件；
* 数据展示方式；
* 空状态、加载状态、错误状态等辅助界面；
* 深浅层级与视觉节奏；
* 必要的动效表现（如适合）。

除非确有必要，请尽量避免依赖外部 CDN 或网络资源，保证 HTML 可以离线浏览。

不要修改现有业务代码，仅在 `docs\zyz\design-rebuild\demo` 下新增内容。

如果输出多个方案，请同时生成 `docs\zyz\design-rebuild\demo\README.md`，内容包括：

* 每个方案的设计理念；
* 采用了哪些 `.agents\skills` 中的参考；
* 适用场景；
* 与现有设计相比的主要变化；
* 推荐程度及原因。

最终交付物应能够作为项目视觉重构评审材料，而不是最终产品实现代码。重点应放在设计质量、设计一致性和表达完整性，而非工程实现。
