# Order Command Agent 本地开发调试手册

更新时间：2026-07-07

## 1. 项目组成

本项目当前由三部分组成：

| 部分 | 本地目录 | 技术栈 | 默认端口 | 说明 |
| --- | --- | --- | --- | --- |
| 前端 | `D:\CodexWorkSpace\ordercommandfrontend` | Vite + React + TypeScript | `5173` | 页面入口，开发态通过 Vite proxy 访问后端接口 |
| Java 后端 | `D:\CodexWorkSpace\ordercommandbackend` | Spring Boot 3.4 + Maven 多模块 | `18888` | 提供 `/inter-api/order-command-agent/**` 业务接口 |
| Agent 服务端 | `D:\CodexWorkSpace\ordercommandagentservice\agent-service` | Node.js + TypeScript | `3002` | 提供 REST API、`/health`、`/logs`、`/ws/agent` |

期望的本地调用关系：

```text
浏览器 / 前端 dev server
  -> http://localhost:3002             Agent REST / WebSocket
  -> http://localhost:18888            Java 业务后端
  -> https://ubddev.supcon.com:8080    认证系统 getCurrentLoginInfo

Agent 服务
  -> http://localhost:18888/api        Java 后端业务接口，代码会将 /api 映射到 /inter-api/order-command-agent
  -> LLM API                           由 llm.config.json 配置
```

注意：认证接口仍保留远程认证系统，因为当前 Java 后端并没有实现 `/inter-api/auth/v1/getCurrentLoginInfo` 这个 Controller；Java 后端只是会调用该远程认证地址来校验 ticket。

## 2. 已完成的本地环境调整

### 2.1 前端本地环境变量

文件：

```text
D:\CodexWorkSpace\ordercommandfrontend\.env.development.local
```

当前内容：

```env
# Local development proxy for the local backend + agent-service.
# This file is ignored by Git via the existing "*.local" rule.
VITE_AGENT_BASE_URL=http://localhost:3002
ORDERCOMMAND_AUTH_PROXY_TARGET=https://ubddev.supcon.com:8080
ORDERCOMMAND_INTER_API_PROXY_TARGET=http://localhost:18888
```

含义：

| 变量 | 含义 |
| --- | --- |
| `VITE_AGENT_BASE_URL` | 浏览器端直接访问 Agent 服务，包含 REST 和 WebSocket |
| `ORDERCOMMAND_AUTH_PROXY_TARGET` | Vite dev server 将认证接口代理到远程认证系统 |
| `ORDERCOMMAND_INTER_API_PROXY_TARGET` | Vite dev server 将业务 `/inter-api/**` 代理到本地 Java 后端 |

### 2.2 Agent 服务本地环境变量

文件：

```text
D:\CodexWorkSpace\ordercommandagentservice\agent-service\.env
```

当前内容：

```env
PORT=3002
# LLM 配置已迁移到 llm.config.json
CLAW_BINARY_PATH=
SKILLS_DIR=../.claw/skills
BACKEND_API_URL=http://localhost:18888/api
FRONTEND_URL=http://localhost:5173/ordercommand
AGENT_SERVICE_URL=http://127.0.0.1:3002
```

说明：

| 变量 | 含义 |
| --- | --- |
| `PORT` | Agent 服务监听端口 |
| `BACKEND_API_URL` | Agent 回写会话、任务、日志时访问 Java 后端的基础地址 |
| `FRONTEND_URL` | Agent 生成前端跳转链接时使用的地址；前端 Vite `base` 是 `/ordercommand/` |
| `AGENT_SERVICE_URL` | Agent 内部定时任务回调自身时使用 |
| `SKILLS_DIR` | Agent skill 目录 |
| `CLAW_BINARY_PATH` | claw 可执行文件路径；为空时进入 mock mode |

## 3. 需要人工配置或确认的部分

### 3.1 LLM API Key

配置文件：

```text
D:\CodexWorkSpace\ordercommandagentservice\agent-service\llm.config.json
```

需要确认或替换：

| 配置项 | 说明 |
| --- | --- |
| `providers[].apiKey` | 真实 LLM API Key |
| `providers[].apiUrl` | 模型服务地址 |
| `providers[].proxyUrl` | 如果需要代理，在这里配置 |
| `defaultModel` | 默认使用的模型 ID |

不要把生产 API Key 提交到公共仓库或贴到日志里。

### 3.2 claw / MCP 能力

当前 Agent `.env` 中：

```env
CLAW_BINARY_PATH=
```

为空时服务可以启动，但 MCP 会进入 mock mode。需要真实 MCP/claw 能力时，把 `CLAW_BINARY_PATH` 改成 claw 可执行文件的绝对路径。

### 3.3 Java 后端数据库

Java 后端默认连接配置在：

```text
D:\CodexWorkSpace\ordercommandbackend\order-command-agent-application\src\main\resources\application.yml
D:\CodexWorkSpace\ordercommandbackend\order-command-agent-application\src\main\resources\application-dev.yml
```

默认连接：

```text
MySQL: 10.33.36.109:9894
DB: dingdan
```

如果要完全本地化数据库，需要本机安装 MySQL，创建数据库后导入：

```text
D:\CodexWorkSpace\ordercommandbackend\docs\sql\order_command_schema.sql
D:\CodexWorkSpace\ordercommandbackend\docs\sql\order_command_sample_data.sql
```

然后启动后端前设置：

```powershell
$env:SUPOS_MYSQL_HOST='127.0.0.1'
$env:SUPOS_MYSQL_PORT='3306'
$env:SUPOS_MYSQL_DBNAME='dingdan'
$env:SUPOS_MYSQL_USERNAME='你的用户名'
$env:SUPOS_MYSQL_PASSWORD='你的密码'
```

如果只是为了前后端联调，可以暂时沿用默认远程 MySQL。

### 3.4 Nacos

后端配置中包含 Nacos：

```text
SUPOS_NACOS_ADDRESS 默认 10.40.0.35:8848
```

本地开发建议先关闭 Nacos discovery/config，直接通过 localhost 调试 HTTP 接口。启动命令见后文。

## 4. 推荐启动顺序

### 4.1 启动 Java 后端

进入后端目录：

```powershell
Set-Location D:\CodexWorkSpace\ordercommandbackend
```

首次或代码变更后打包：

```powershell
& 'C:\Users\zhangyingzhong\Documents\Codex\2026-07-07\mo\work\tools\apache-maven-3.9.16\bin\mvn.cmd' -pl order-command-agent-application -am -DskipTests package
```

启动后端：

```powershell
$env:ORDER_COMMAND_AGENT_PORT='18888'
$env:SAL_CONTR_SYNC_ENABLED='false'
$env:DINGTALK_STREAM_ENABLED='false'

java -jar .\order-command-agent-application\target\order-command-agent.jar `
  --spring.cloud.nacos.discovery.enabled=false `
  --spring.cloud.nacos.config.enabled=false
```

说明：

| 参数 | 作用 |
| --- | --- |
| `ORDER_COMMAND_AGENT_PORT=18888` | 与前端本地代理和 Agent `.env` 保持一致 |
| `SAL_CONTR_SYNC_ENABLED=false` | 本地调试关闭销售合同全量同步定时任务，减少外部依赖 |
| `DINGTALK_STREAM_ENABLED=false` | 本地调试关闭钉钉 Stream |
| `spring.cloud.nacos.discovery.enabled=false` | 不注册 Nacos |
| `spring.cloud.nacos.config.enabled=false` | 不从 Nacos 拉配置 |

后端业务接口前缀：

```text
http://localhost:18888/inter-api/order-command-agent
```


## 5. 完整联调检查清单

按顺序检查：

1. Java 后端是否启动在 `18888`。
2. Agent 服务是否启动在 `3002`。
3. 前端是否启动在 `5173`，访问路径是否带 `/ordercommand/`。
4. 浏览器控制台中 Agent WebSocket 是否连接到 `ws://localhost:3002/ws/agent`。
5. 前端业务接口是否请求到 `http://localhost:5173/inter-api/...`，再由 Vite 代理到 `http://localhost:18888`。
6. 认证接口是否仍由 Vite 代理到 `https://ubddev.supcon.com:8080`。
7. Agent 调用 Java 后端时，`BACKEND_API_URL=http://localhost:18888/api` 会在代码里映射到 `/inter-api/order-command-agent`。
8. LLM 请求失败时，优先检查 `llm.config.json` 的 `apiKey`、`apiUrl`、`proxyUrl`。
9. MCP 工具不可用时，检查 `CLAW_BINARY_PATH` 是否为空；为空属于 mock mode。

## 6. 常见问题

### 6.1 前端登录信息接口 404

原因：不要把 `ORDERCOMMAND_AUTH_PROXY_TARGET` 指到本地 Java 后端。当前 Java 后端没有 `/inter-api/auth/v1/getCurrentLoginInfo`。

正确配置：

```env
ORDERCOMMAND_AUTH_PROXY_TARGET=https://ubddev.supcon.com:8080
```

### 6.2 前端业务接口仍访问远程测试后端

检查：

```text
D:\CodexWorkSpace\ordercommandfrontend\.env.development.local
```

确保：

```env
ORDERCOMMAND_INTER_API_PROXY_TARGET=http://localhost:18888
```

修改 `.env.development.local` 后需要重启 Vite dev server。

### 6.3 Agent 生成的前端跳转地址少了 `/ordercommand`

检查 Agent `.env`：

```env
FRONTEND_URL=http://localhost:5173/ordercommand
```

修改后重启 Agent 服务。

### 6.4 PowerShell 执行 npm 报脚本策略错误

现象：

```text
npm.ps1 cannot be loaded because running scripts is disabled
```

解决：使用 `npm.cmd`。

```powershell
npm.cmd run build
npm.cmd run dev
npm.cmd start
```

### 6.5 Maven 命令不可用

当前使用便携 Maven，不依赖系统 PATH：

```powershell
& 'C:\Users\zhangyingzhong\Documents\Codex\2026-07-07\mo\work\tools\apache-maven-3.9.16\bin\mvn.cmd' -v
```

如后续希望 IDE 和普通终端直接识别 `mvn`，可以手动安装完整版 Maven，并配置：

```text
MAVEN_HOME=你的 Maven 安装目录
Path += %MAVEN_HOME%\bin
```

### 6.6 Java 后端启动后数据库连接失败

检查后端日志里的 MySQL 地址。默认配置会连远程 `10.33.36.109:9894/dingdan`。

如果使用本地 MySQL，启动前设置：

```powershell
$env:SUPOS_MYSQL_HOST='127.0.0.1'
$env:SUPOS_MYSQL_PORT='3306'
$env:SUPOS_MYSQL_DBNAME='dingdan'
$env:SUPOS_MYSQL_USERNAME='你的用户名'
$env:SUPOS_MYSQL_PASSWORD='你的密码'
```

并确认已导入：

```text
docs\sql\order_command_schema.sql
docs\sql\order_command_sample_data.sql
```

### 6.7 Nacos 连接或注册异常

本地开发建议直接关闭：

```powershell
java -jar .\order-command-agent-application\target\order-command-agent.jar `
  --spring.cloud.nacos.discovery.enabled=false `
  --spring.cloud.nacos.config.enabled=false
```

### 6.8 Agent health 正常但模型对话失败

优先检查：

```text
D:\CodexWorkSpace\ordercommandagentservice\agent-service\llm.config.json
```

重点项：

```json
{
  "providers": [
    {
      "apiKey": "替换为真实 Key",
      "apiUrl": "模型服务地址",
      "proxyUrl": "如需代理则配置"
    }
  ],
  "defaultModel": "可用模型 ID"
}
```
