# 01 能力模型与路线图

> 本章解决的问题：**你现在在哪、要去哪、每一段路用什么证据证明自己到了。**

---

## 一、把"全栈安全工程师"拆成四张地图

安全行业里没有人真的"什么都会"。所谓全栈，是指你同时具备四种视角，并且能在同一个系统上把它们串起来：

| 地图 | 核心问题 | 典型产出 | 常见岗位 |
|---|---|---|---|
| **攻（Offense）** | 这个系统能被怎么打穿？ | 渗透测试报告、漏洞 PoC、红队战报 | 渗透测试、红队、漏洞研究 |
| **防（Defense）** | 打穿时我能不能看见、能不能拦住？ | 检测规则、应急预案、取证报告 | SOC、DFIR、威胁狩猎、检测工程 |
| **建（Build）** | 怎样让系统一开始就难以被打穿？ | 安全架构、代码审计、安全流水线 | AppSec、DevSecOps、云安全、安全研发 |
| **治（Govern）** | 组织怎样持续管理风险、满足合规？ | 风险评估、制度、审计证据 | 安全咨询、GRC、CISO 路线 |

"全栈"不是四张地图都画到最深，而是：

- 四张地图都能读懂，能和对应岗位的人用同一套语言讨论；
- 至少一张地图能独立带队走完一个完整项目；
- 知道另外三张地图的**边界**和**交接点**，不越界、不甩锅。

## 二、能力等级：用行为定义，不用感觉定义

| 等级 | 名称 | 行为标准 | 证据 |
|---|---|---|---|
| L0 | 不知道 | 没听过这个概念，或只知道名词 | 无 |
| L1 | 知道 | 能用自己的话解释概念，知道它解决什么问题 | 笔记、口头复述 |
| L2 | 能复现 | 照着文档/教材能在实验环境完成标准任务 | 实验记录、截图、命令历史 |
| L3 | 能独立 | 不给步骤，只给目标，能独立完成并排错 | 项目、报告、代码 |
| L4 | 能设计 | 能设计新方案、做取舍、迁移到没见过的场景、能审别人的方案 | 架构文档、code review、带人 |
| L5 | 能研究/教学 | 能发现新问题、定义方法、教出 L3 的人 | 论文、演讲、开源、课程 |

**判定规则**：不要用"我学过"给自己评级，用"我能否在不看答案的情况下做出证据"评级。L2 到 L3 的分界线是**排错能力**；L3 到 L4 的分界线是**取舍能力**。

## 三、目标能力矩阵

下表是"初级全栈安全工程师"的目标。不是让你同时达到，而是让你知道每一格应该到什么程度。

| 领域 | 目标等级 | 达标的最低证据 | 对应章节 |
|---|---|---|---|
| 数学基础 | L3 | 能读懂密码学/概率/图论中的定义与证明，能用手算+代码验证 | 03 |
| 计算机科学基础 | L3 | 能解释一次 HTTP 请求从网卡到进程的完整路径 | 04 |
| 编程与工程 | L4 | 能独立写 500～1000 行带测试的工具，能读栈回溯排错 | 05 |
| Linux/Windows 系统 | L3 | 能手工排查权限、进程、网络、日志问题 | 04、08 |
| 网络协议 | L4 | 能用 tcpdump/Wireshark 解释一次 TCP/TLS 交互并定位异常 | 04 |
| 密码学 | L3 | 能选对原语、看出常见误用、解释 TLS 1.3 握手 | 06 |
| Web 安全 | L4（若主攻）/ L3（否则） | 能独立完成一次 Web 应用测试并给出修复方案 | 06 |
| 二进制与逆向 | L2～L3（若主攻则 L4） | 能分析简单 ELF/PE、解释漏洞机理、写基础 PoC | 07 |
| 蓝队/检测/DFIR | L3 | 能独立完成告警 triage、写 Sigma 规则、做一次小型应急 | 08 |
| 云原生与供应链 | L3 | 能审计一个云账号/K8s 集群并给出加固方案 | 09 |
| 治理与合规 | L3 | 能做风险登记、控制映射、写管理制度 | 10 |
| 写作与表达 | L4 | 报告能让非技术管理层读懂、让技术同行复现 | 12 |
| 英语 | L3 | 能读 RFC/官方文档/论文，能写简单技术邮件 | 全程 |

**主攻方向**：第 10 个月前必须选一个，目标 L4；其余方向保持 L2～L3。主攻方向决定你的第一份工作，广度决定你三年后的天花板。

## 四、24 个月阶段计划

### 阶段 0：校准（第 0～2 周，约 30 小时）

**目标**：把"想学"变成"有环境、有基线、有契约"。

- 搭好隔离实验环境（见 11 章）。
- 做基线测试（见 14 章），记录分数。
- 写学习契约（见本章第六节）。
- 选定主攻方向的**候选**（可以暂定，第 9 月再确认）。
- 建立 Git 仓库、笔记系统、Anki 牌组。
- 读完 02 章，按里面的规则开始第一周。

**出口**：能在 30 分钟内启动实验环境；能说清楚自己为什么学安全、想解决什么问题；有一份签了名的学习契约。

---

### 阶段 1：地基（第 1～4 月，约 280 小时）

**目标**：补上数学和计算机科学的地基，能读懂后续所有安全材料。

| 模块 | 学时 | 内容 | 证据 |
|---|---|---|---|
| 数学 I | 80h | 离散数学、线性代数、概率统计 | 3 套习题 + 1 份"数学在安全中的用途"笔记 |
| CS 基础 | 80h | 组成原理、操作系统、数据结构 | 手写 toy shell / HTTP server |
| 编程 | 60h | Python + C + Git | 2 个 CLI 工具 + 测试 |
| 网络 | 50h | TCP/IP、HTTP、DNS、TLS 基础 | 抓包分析报告 |
| 安全素养 | 10h | CIA、威胁建模、风险、认证授权 | 一份个人项目威胁模型 |

**出口考试**：
1. 不看资料画出一次 HTTPS 请求的完整路径（DNS → TCP → TLS → HTTP → 服务端 → 数据库 → 返回）。
2. 用 Python 写一个支持并发的端口扫描器，用 C 写一个能处理 `SIGINT` 的 TCP 回显服务器。
3. 用 Wireshark 分析一个 pcap，指出 TCP 三次握手、TLS ClientHello、HTTP 请求、异常重传。
4. 解释 RSA 的数学基础，并手算一个玩具例子。

---

### 阶段 2：安全核心（第 5～9 月，约 360 小时）

**目标**：建立"攻防两边都懂"的核心能力。

| 模块 | 学时 | 内容 | 证据 |
|---|---|---|---|
| 密码学 | 60h | 对称/公钥/哈希/MAC/PKI/TLS/常见误用 | 玩具 RSA/DH 实现 + TLS 抓包分析 |
| Web 安全 | 120h | OWASP Top 10:2025 + 常见扩展漏洞 + 测试方法 | 50 个 PortSwigger lab + 1 份测试报告 |
| 系统安全 | 70h | Linux/Windows 权限、加固、AD 基础 | Linux/Windows 加固基线 |
| 网络防御 | 50h | 防火墙、IDS/IPS、分段、VPN、DNS 安全 | 家庭/实验网络威胁模型 + 防火墙规则 |
| 安全工具 | 40h | Nmap、Burp、Wireshark、Metasploit（仅靶场） | 工具原理笔记，不抄命令 |
| 写作 | 20h | 漏洞报告、修复建议 | 1 篇可复现的漏洞分析 |

**出口考试**：
1. 在 PortSwigger Academy 完成至少 50 个 Apprentice/Practitioner lab，覆盖 SQLi、XSS、CSRF、SSRF、访问控制、认证、文件上传、命令注入。
2. 对一个自己写的 Web 应用完成"攻击 → 修复 → 回归测试"闭环，提交代码 diff。
3. 解释 Kerberos 认证流程，画出 AD 中一次登录的票据流转。
4. 给一个中小型网络写 10 条防火墙/分段策略，并说明每条对应的威胁。

---

### 阶段 3：专精（第 10～14 月，约 360 小时）

**目标**：选一个主攻方向做到 L4，同时用"对照表"补齐其他方向到 L2～L3。

| 主攻方向 | 核心任务 | 出口证据 |
|---|---|---|
| **Web/AppSec** | 完成 PortSwigger Practitioner 大部分 + 代码审计 + 1 个开源项目审计 | 3 份 Web 测试报告 + 1 份代码审计报告 |
| **二进制/逆向** | pwn.college + ROP Emporium + 逆向 10 个 crackme + Fuzzing | 20 道 pwn writeup + 1 份 Fuzzing 报告 |
| **蓝队/DFIR** | 检测工程 + 事件响应 + 内存取证 | 20 条 Sigma + 1 份应急报告 + 1 份取证报告 |
| **云安全** | AWS/Azure/阿里云 + K8s + CI/CD | 1 份云安全评估 + 1 个加固后的 K8s 集群 |

**共同作业（不管主攻什么）**：
- 读 3 份真实公开的漏洞报告/事件报告，写"如果是我，怎么发现/怎么防"。
- 完成一次 4 小时限时靶场，并写复盘。
- 参加一次 CTF（线上即可），至少完成 3 题，写 writeup。
- 做一次"红队自己"：用阶段 1～2 的知识攻击自己的项目，记录盲区。

**出口考试**：
1. 主攻方向：一份 15 页以上的完整报告，包含范围、方法、发现、影响、修复、附录。
2. 非主攻方向：能向该方向工程师提出 5 个不失礼、不失焦的问题。
3. 能在 30 分钟内把一个复杂漏洞讲给非技术听众听。

---

### 阶段 4：工程化（第 15～19 月，约 360 小时）

**目标**：从"会做一次"变成"能放进组织流程里持续做"。

| 模块 | 学时 | 内容 | 证据 |
|---|---|---|---|
| 安全 SDLC | 50h | 威胁建模、安全需求、代码审计、SAST/DAST/SCA | 一个项目的威胁模型 + 安全需求清单 |
| CI/CD 与供应链 | 70h | 流水线威胁、SBOM、SLSA、签名、依赖安全 | 一条带安全门禁的流水线 |
| 云与 K8s | 90h | IAM、网络、日志、RBAC、准入控制、运行时安全 | 云账号评估 + K8s 加固报告 |
| 检测工程 | 60h | 遥测、Sigma、ATT&CK 映射、调优 | 检测规则库 + 测试记录 |
| 合规与风险 | 50h | NIST CSF 2.0、ISO 27001、等保 2.0、风险登记 | 风险登记表 + 控制映射矩阵 |
| AI 安全 | 40h | LLM Top 10、提示注入、数据/模型供应链、治理 | LLM 应用威胁模型 + 安全使用规范 |

**出口考试**：
1. 给一个包含 Web、数据库、对象存储、K8s 的系统画威胁模型（STRIDE），列出 10 个威胁和对应控制。
2. 建一条 CI/CD 流水线：提交 → 测试 → SAST → 依赖扫描 → 镜像签名 → 部署到 K8s，并故意引入一个漏洞验证门禁能拦住。
3. 写 10 条 Sigma 规则，用 Atomic Red Team 或手工模拟验证，记录误报和调优过程。
4. 把等保 2.0 的 10 个控制项映射到具体技术措施和证据。

---

### 阶段 5：综合与职业化（第 20～24 月，约 360 小时）

**目标**：用一个完整的 Capstone 把所有能力串起来，并把它变成求职资产。

**Capstone 建议**：搭一个"迷你企业"：
- 1 个 Windows AD 域（DC + 2 台成员机）
- 1 个 Web 应用（含数据库、对象存储）
- 1 个 K8s 集群（或云上托管服务）
- 1 套 SIEM（Splunk Free / Elastic / Wazuh）
- 1 套检测规则和应急手册

然后做一次**红蓝对抗演练**：
1. 红队：从外网边界打到域控，记录 ATT&CK 技术编号。
2. 蓝队：只靠日志和告警发现、定位、遏制、恢复。
3. 复盘：哪些攻击没被看见？哪些告警是噪声？补什么规则、改什么架构？
4. 产出：红队报告 + 蓝队报告 + 管理层摘要 + 修复计划。

**求职动作**（从第 20 月开始）：
- 作品集：GitHub + 博客 + 3 份脱敏报告。
- 简历：一页，项目导向，量化结果。
- 面试：技术题 + 行为题 + 反向提问。
- 投递：先实习/初级岗，再谈方向；不要只盯"红队"。

**出口**：Capstone 报告 + 作品集 + 至少 10 次有效面试/模拟面试。

---

### 阶段 6：长期（第 25 月起）

- 选一个细分方向持续 2～3 年：漏洞研究、检测工程、云安全架构、工控、AI 安全、密码学工程等。
- 每年至少：1 次会议/Meetup 演讲、1 个开源贡献、1 篇深度长文、1 次带新人。
- 认证按职业阶段选，不按"收集癖"选（见 [15-认证与职业路径](15-认证与职业路径.md)）。

## 七、阶段复盘的四个问题

每 3 个月，用一页纸回答：

1. **我做出了什么？** 列出可验证的产出（代码、报告、规则、文章），不是"看了什么"。
2. **我卡在哪里？** 是概念不清、环境问题、时间不够，还是动机下降？
3. **我下一步最小的动作是什么？** 小到今天/本周就能做。
4. **我要删掉什么？** 哪些资源、项目、目标已经不再重要？

> 如果第 3 个问题答不出来，说明目标太大；如果第 4 个问题答不出来，说明你在囤积而不是学习。

## 八、不要做的事

- 不要同时开 5 门课。一次只主攻 1 个模块 + 1 个长期项目。
- 不要用"看完视频"当完成。视频只是地图，实验才是走路。
- 不要用"考完证"当能力证明。证书是门票，报告和代码才是战绩。
- 不要在没学概率之前去调检测规则，也不要在没学内存之前去刷 pwn 题。
- 不要因为"全栈"就拒绝选方向。没有纵深的全栈，只是浅尝辄止。
