# 10 治理、合规与职业伦理

> 本章解决的问题：**技术决定你能做什么，治理决定你该做什么、做到什么程度、出了事谁负责。**

很多技术型安全人员把合规当成"填表"，把治理当成"管理层的事"。这是一个危险的误解：**没有治理的技术，无法规模化；没有伦理的技术，迟早出事。**

---

## 一、基本概念：先把词用对

| 概念 | 定义 | 常见误区 |
|---|---|---|
| 资产（Asset） | 对组织有价值的信息、系统、服务、人员 | 只算服务器，不算数据和声誉 |
| 威胁（Threat） | 可能造成损害的来源 | 把威胁和漏洞混为一谈 |
| 脆弱性（Vulnerability） | 可被威胁利用的弱点 | 只算技术漏洞，忽略流程和人 |
| 风险（Risk） | 威胁利用脆弱性造成影响的可能性与后果 | 只用"高/中/低"，不写假设 |
| 控制（Control） | 降低风险的措施 | 以为买了设备就等于有控制 |
| 残余风险（Residual Risk） | 实施控制后仍存在的风险 | 假设控制 100% 有效 |
| 纵深防御（Defense in Depth） | 多层独立控制 | 同一控制重复买三份 |
| 最小权限（Least Privilege） | 只给完成工作所需的最小权限 | 给"临时方便"开永久后门 |
| 职责分离（Separation of Duties） | 关键操作需多人/多角色 | 一个人既能改代码又能审代码 |
| 零信任（Zero Trust） | 不默认信任任何网络位置，持续验证 | 以为买了零信任产品就零信任了 |

**风险公式**（定性）：`风险 = 可能性 × 影响`。定量可以用 `ALE = SLE × ARO`（年化损失 = 单次损失 × 年发生频率），但不要假装精确到小数点。

**风险处置**：规避（Avoid）、降低（Mitigate）、转移（Transfer，如保险）、接受（Accept）。每个处置都要有责任人、期限、残余风险说明。

## 二、框架：从"做什么"到"怎么证明"

### NIST CSF 2.0（2024）

六个功能：**Govern、Identify、Protect、Detect、Respond、Recover**。

- Govern 是 2.0 新增的核心，强调治理、风险策略、供应链、角色责任。
- 适合用来给管理层讲"我们的安全体系覆盖了什么、缺什么"。
- 不是认证标准，是风险管理框架。

### ISO/IEC 27001:2022

- 信息安全管理体系（ISMS）；认证标准。
-  Annex A 控制项分为组织、人员、物理、技术四类。
- 核心不是文档，而是"风险评估 → 控制选择 → 运行 → 内审 → 改进"的闭环。
- 适合对外证明"我们有体系"，但落地质量取决于执行。

### 其他

- **SOC 2**：面向服务商，关注安全、可用性、处理完整性、保密性、隐私。
- **PCI DSS 4.0**：支付卡行业；要求细，适合学习"控制如何落到具体配置"。
- **GDPR**：欧盟个人数据保护；关注合法性基础、数据主体权利、跨境传输、DPIA。
- **NIST SP 800-53**：控制目录，适合做控制映射。
- **CIS Controls**：优先级明确的18项控制，适合中小企业落地。
- **MITRE ATT&CK/D3FEND**：技术侧，和治理框架互补。

### 中国法规体系（学习索引）

> 以下只做学习索引，不构成法律意见。具体适用请咨询律师/合规负责人，并以官方最新文本为准。

| 法规/标准 | 生效/版本 | 与安全工程师的关系 |
|---|---|---|
| 《网络安全法》 | 2017-06-01 施行；2025-10-28 修改，2026-01-01 施行 | 网络运营者义务、等级保护、日志留存、事件报告、AI 安全条款 |
| 《数据安全法》 | 2021-09-01 | 数据分类分级、重要数据、风险评估、出境 |
| 《个人信息保护法》 | 2021-11-01 | 告知同意、最小必要、敏感个人信息、跨境、个人权利 |
| 《网络数据安全管理条例》 | 2025-01-01 | 细化数据安全、个人信息、重要数据、跨境、平台义务 |
| 《关键信息基础设施安全保护条例》 | 2021-09-01 | CII 识别、保护、检测、演练、报告 |
| 《密码法》 | 2020-01-01 | 商用密码、关键设备认证、合规使用 |
| 等保 2.0（GB/T 22239-2019 及配套） | 2019-12-01 | 定级、备案、建设整改、测评、监督检查 |
| 《网络安全审查办法》 | 2022-02-15 | 关键信息基础设施采购、数据出境风险 |
| 《数据出境安全评估办法》 | 2022-09-01 | 数据出境评估、标准合同、认证 |
| 《生成式人工智能服务管理暂行办法》 | 2023-08-15 | 生成式 AI 服务合规、训练数据、内容标识 |
| 《人工智能生成合成内容标识办法》 | 2025-09-01 | AI 生成内容标识、显式/隐式标识 |
| 《刑法》第 285/286/287 条之二等 | 现行 | 非法侵入、破坏、提供工具、帮信等刑事责任 |

**等保 2.0 的核心流程**：定级 → 备案 → 建设整改 → 等级测评 → 监督检查。技术层面看"安全物理环境、安全通信网络、安全区域边界、安全计算环境、安全管理中心"；管理层面看制度、机构、人员、建设、运维。

**合规不是"买产品"**：等保要求的是"控制措施 + 证据 + 持续运行"，不是一堆设备清单。

## 三、风险管理：把"我觉得"变成"可讨论"

### 3.1 资产与业务影响分析（BIA）

- 列出关键业务：支付、登录、订单、数据查询、内部办公。
- 每个业务依赖哪些系统、数据、供应商、人员。
- 中断 1 小时/1 天/1 周的损失（收入、声誉、合规、安全）。
- 恢复时间目标（RTO）、恢复点目标（RPO）。

### 3.2 威胁建模

- **STRIDE**：仿冒、篡改、否认、信息泄露、拒绝服务、权限提升。
- 步骤：画数据流图 → 标信任边界 → 列威胁 → 定控制 → 验证。
- 产出：威胁清单、控制映射、残余风险、责任人。

### 3.3 风险登记表

至少包含：

| 字段 | 说明 |
|---|---|
| ID | R-001 |
| 资产/业务 | 支付 API |
| 威胁 | 攻击者利用 SSRF 访问云元数据 |
| 脆弱性 | 未限制出口、IMDSv1 未禁用 |
| 可能性 | 中（有公开利用手法） |
| 影响 | 高（可获取临时凭证） |
| 现有控制 | WAF、日志 |
| 建议控制 | 禁用 IMDSv1、出口白名单、最小角色 |
| 责任人/期限 | 平台组/30 天 |
| 残余风险 | 低 |
| 状态 | 处理中 |

### 3.4 安全指标

- 技术：漏洞修复时长、补丁覆盖率、MFA 覆盖率、检测覆盖率、MTTD/MTTR。
- 治理：风险评估完成率、供应商评估覆盖率、培训完成率、演练次数。
- 不要用"告警数量""拦截次数"当唯一 KPI。

## 四、制度与运营

一个最小可用的安全制度集：

1. 信息安全方针（总纲）。
2. 资产管理（分类分级、责任人）。
3. 访问控制（账号、权限、评审、离职）。
4. 变更管理（上线、回滚、审批）。
5. 漏洞管理（发现、定级、修复、例外）。
6. 事件响应（分级、上报、处置、复盘）。
7. 业务连续性/灾难恢复（BIA、RTO/RPO、演练）。
8. 供应商/供应链安全。
9. 数据安全与隐私（分类、加密、脱敏、跨境）。
10. 安全培训与意识。
11. 物理与环境安全（如适用）。
12. 开发安全（SDL、代码审计、上线门禁）。

**制度落地的三个关键**：

- **有人负责**：每项控制有 owner，不是"安全部"一个部门。
- **有证据**：日志、工单、截图、审批记录、测评报告。
- **有改进**：内审、演练、事件复盘，形成闭环。

## 五、职业伦理与法律边界

### 5.1 授权是唯一的前提

- 书面授权：范围、时间、目标、禁止项、联系人、应急流程。
- 口头授权不算；聊天记录不算；"我是为了研究"不算。
- 授权范围外的系统，即使你能进，也不能进。
- 测试中发现的真实数据，不下载、不传播、不利用。

### 5.2 漏洞披露

- **负责任披露**：先私下联系厂商，给修复时间，再公开。
- **协调披露**：通过 CERT/CNVD/CNNVD 等渠道。
- **漏洞赏金**：严格按 scope，不碰第三方系统，不公开未修复细节。
- **不要**：勒索、公开 0day 利用代码、倒卖漏洞、攻击关基设施。

### 5.3 法律红线（中国）

- 非法侵入计算机信息系统罪（刑法 285 条）。
- 非法获取计算机信息系统数据、非法控制计算机信息系统罪。
- 提供侵入、非法控制计算机信息系统的程序、工具罪。
- 破坏计算机信息系统罪（286 条）。
- 帮助信息网络犯罪活动罪（287 条之二）。
- 侵犯公民个人信息罪（253 条之一）。
- 《网络安全法》《数据安全法》《个人信息保护法》的行政责任。

> 不构成法律意见。涉及具体行为，先问律师。

### 5.4 伦理困境

- 发现公司系统的高危漏洞，但领导要求"先上线再说"。
- 发现同事/上级的违规操作。
- 客户要求"测试一下竞争对手"。
- 漏洞赏金中发现超出 scope 的敏感数据。
- 自己的工具被用于攻击。

**处理原则**：写下来、找合规/法务、保留证据、按流程上报；不要自行"正义执行"，也不要沉默。

## 六、把治理变成技术动作

| 治理要求 | 技术落地 | 证据 |
|---|---|---|
| 最小权限 | IAM 策略、RBAC、sudo 规则 | 权限矩阵、评审记录 |
| 日志留存 6 个月 | 集中日志、冷存储、完整性 | 日志平台配置、查询截图 |
| 漏洞管理 | 扫描、SBOM、补丁 SLA | 漏洞工单、修复记录 |
| 变更管理 | GitOps、审批、回滚 | PR、流水线记录 |
| 事件响应 | SIEM 告警、runbook、演练 | 演练报告、时间线 |
| 数据分类 | 标签、DLP、加密 | 数据地图、分类清单 |
| 供应链 | SBOM、签名、供应商评估 | SBOM、签名验证、评估表 |
| 等保 | 基线加固、测评整改 | 基线报告、测评报告 |
