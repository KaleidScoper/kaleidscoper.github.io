# 07 二进制安全与逆向

> 本章解决的问题：**当漏洞不在 HTTP 参数里，而在内存、指令和文件格式里，你还能不能看见它。**

> **安全边界**：本章只讨论原理、防御和**本地/授权靶场**中的实验。不提供针对真实目标的利用步骤、武器化代码或绕过执法/取证的方法。所有实验必须在隔离虚拟机中进行。

---

## 一、这条路的入口与代价

二进制安全是安全行业里学习曲线最陡的方向之一。它要求你同时具备：

- C 语言和内存模型；
- x86-64 汇编与调用约定；
- 操作系统（进程、虚拟内存、加载器）；
- 编译/链接/ELF/PE；
- 调试器与逆向工具；
- 足够的耐心（一个洞可能要看几天）。

**回报**：你能理解漏洞的"最后一公里"，能分析恶意样本，能写 fuzzer，能做漏洞研究，能在红队/蓝队/取证之间自由切换。

**代价**：前 3 个月进步很慢，容易挫败。建议先完成第 04、05 章，再进入本章。

## 三、二进制格式与加载

### ELF（Linux）

- 文件头、程序头（segment）、节头（section）。
- `.text`、`.data`、`.bss`、`.rodata`、`.plt`、`.got`、`.init_array`、`.fini_array`。
- 符号表、动态符号表、重定位。
- 静态链接 vs 动态链接；解释器 `/lib64/ld-linux-x86-64.so.2`。
- `readelf -h/-l/-S/-s/-r/-d`。

### PE（Windows）

- DOS 头、NT 头、节表、导入表、导出表、重定位、资源。
- `.text`、`.rdata`、`.data`、`.rsrc`、`.reloc`。
- DLL、导入地址表（IAT）、延迟加载。
- 工具：`dumpbin`、PE-bear、CFF Explorer、`pefile`。

### 加载与链接

- 编译 → 汇编 → 链接 → 加载。
- 静态链接把库代码复制进可执行文件；动态链接在运行时解析符号。
- PLT/GOT：延迟绑定；第一次调用时解析地址。
- ASLR/PIE：加载地址随机化；GOT 覆写与信息泄露的关系。

**练习**：

1. 用 `readelf` 分析 `/bin/ls`，列出它依赖的库、节、符号。
2. 写一个多文件 C 项目，分别静态/动态链接，比较体积和 `ldd` 输出。
3. 用 `LD_DEBUG=libs,bindings` 观察动态链接过程。
4. 用 `objdump -d` 找一个 `main` 函数，标出参数传递和栈帧。

## 四、内存与漏洞类型

### 栈

- 栈帧：返回地址、保存的 `rbp`、局部变量、参数。
- 栈溢出：越界写覆盖返回地址/保存的寄存器/局部变量。
- 栈 Canary：在返回地址前放一个随机值，函数返回前检查。
- 栈 pivot：改变 `rsp`，把栈迁移到可控内存。

### 堆

- `malloc/free` 的元数据、chunk、bin（tcache/fastbin/smallbin/unsortedbin）。
- 堆溢出、UAF（释放后使用）、double free、类型混淆。
- 堆布局与"风水"：通过分配/释放顺序控制对象位置。
- 现代分配器的缓解：safe-linking、tcache key、随机化。

### 其他

- 整数溢出/截断：长度计算错误导致越界。
- 格式化字符串：`printf(user_input)` 导致任意读写。
- 竞态条件：TOCTOU、信号处理、多线程。
- 越界读：信息泄露（ASLR 绕过、密钥泄露）。
- 未初始化内存：信息泄露、逻辑错误。
- 类型混淆：把 A 类型当 B 类型用。
- 内核漏洞：UAF、越界、竞态、提权；学习曲线更陡。

**练习（本地）**：

1. 写一个带栈溢出的 C 程序，用 gdb 观察返回地址被覆盖，再启用 Canary/NX/PIE 观察变化。
2. 写一个 UAF 的 C++ 程序，用 ASan 定位。
3. 写一个格式化字符串漏洞，观察 `%p`/`%n` 的影响，再修复。
4. 用 `checksec` 看一个二进制的保护机制，逐项解释。

## 五、缓解机制（先懂防御，再懂绕过）

| 机制 | 作用 | 局限/绕过思路（概念级） |
|---|---|---|
| NX/DEP | 栈/堆不可执行 | ROP/JOP、`mprotect`、`ret2libc` |
| ASLR | 随机化基址 | 信息泄露、暴力、部分覆盖 |
| PIE | 可执行文件基址随机 | 同上 |
| Stack Canary | 检测栈溢出 | 泄露 canary、覆盖不触发 canary 的路径、`__stack_chk_fail` 劫持 |
| RELRO | 保护 GOT | Partial RELRO 仍可写；Full RELRO 需其他目标 |
| CFG/CET | 控制流完整性 | 合法目标复用、异常处理、JOP |
| FORTIFY | 编译期/运行期检查 | 覆盖不到的函数、逻辑漏洞 |
| seccomp | 限制 syscall | 逻辑漏洞、允许的 syscall 滥用 |

> 学习顺序：先理解每个机制**防什么**，再在靶场里看**为什么还能被绕过**。不要一上来背绕过技巧。

## 六、利用概念（只到"理解"层）

- **ret2text**：覆盖返回地址到程序内已有代码（如 `system@plt`）。
- **ret2libc**：泄露 libc 基址，调用 `system("/bin/sh")`。
- **ROP**：用 gadget 拼出任意操作；`pop rdi; ret` 等。
- **SROP**：利用 `sigreturn` 构造寄存器上下文。
- **Heap exploitation**：tcache poisoning、UAF、overlap、house of *（了解概念即可）。
- **Kernel exploitation**：UAF/越界 → 提权；需要理解 `cred`、`modprobe_path`、`msg_msg` 等。
- **Browser exploitation**：JIT、类型混淆、沙箱逃逸；难度高，建议后期。

**实验平台**：

- pwn.college（系统化课程，首选）。
- ROP Emporium（ROP 专项）。
- Exploit Education（Phoenix/Nebula）。
- How2Heap（堆利用概念，配合本地 glibc）。
- pwnable.tw / pwnable.kr（经典题）。
- HTB/TryHackMe 的 pwn 路径。

**交付**：

- [ ] 20 道 pwn 题，每题一篇 writeup：保护机制、漏洞点、利用思路、失败尝试、修复建议。
- [ ] 1 份"从漏洞到补丁"的完整分析（自己写的 vulnerable 程序）。
- [ ] 1 份 fuzzing 报告（见下）。

## 七、Fuzzing：让程序自己暴露问题

### 核心概念

- 目标：找到 crash、hang、内存错误、逻辑异常。
- 覆盖率：代码覆盖率、边覆盖率；反馈驱动。
- 语料库：种子、变异、字典、结构感知。
- 工具：AFL++、libFuzzer、honggfuzz、Boofuzz（协议）。
-  sanitizer：ASan、UBSan、MSan、TSan。
- 三角定位：crash 去重、最小化、根因分析。

### 实验

1. 选一个开源解析器（如 libpng、libxml2、json-c 的小版本），用 AFL++ 跑 24 小时。
2. 用 libFuzzer 写一个 harness，fuzz 一个自己写的解析函数。
3. 对 crash 做 triage：ASan 报告、调用栈、是否可利用。
4. 写报告：目标、方法、覆盖率、发现、复现、修复建议。

### 资源

- AFL++ 文档。
- 《Fuzzing Book》（免费）。
- Google OSS-Fuzz 文档。
- 《Practical Binary Analysis》第 8～10 章。

## 八、逆向工程

### 静态分析

- 反汇编：`objdump`、Ghidra、IDA Free、Binary Ninja（选）。
- 反编译：Ghidra 的 decompiler；理解伪代码不等于源码。
- 字符串、导入表、符号、节区、编译器指纹。
- 控制流图、交叉引用、调用链。
- 反混淆：去花指令、字符串解密、控制流平坦化（进阶）。

### 动态分析

- 调试器：gdb/pwndbg、x64dbg、WinDbg。
- 断点：软件/硬件/内存/条件断点。
- 跟踪：`strace`、`ltrace`、API Monitor、Procmon。
- 沙箱：Cuckoo、CAPE、Any.Run、Hybrid Analysis（注意样本安全）。
- 网络：Wireshark、FakeNet-NG、INetSim。

### 练习

1. 逆向 10 个 crackme（从简单到难），写"输入校验逻辑"分析。
2. 用 Ghidra 分析一个开源 CLI 工具，画出主流程。
3. 分析一个加壳样本（UPX 等），脱壳后看导入表。
4. 分析一个简单的恶意样本（在隔离环境），写 IOC 和 YARA 规则。

### 资源

-《Reverse Engineering for Beginners》（Dennis Yurichev，免费）。
-《Practical Binary Analysis》。
-《The IDA Pro Book》（选读）。
- Ghidra 官方教程。
- Malware Unicorn 逆向工作坊。
- FLARE VM / REMnux。

## 九、恶意样本分析（安全第一）

### 铁律

1. 只在**隔离虚拟机**中运行，禁用共享文件夹、剪贴板、USB、网络桥接。
2. 样本来源合法（公开研究样本、MalwareBazaar 等），不分析来源不明的真实攻击样本。
3. 不上传客户/学校/公司的真实数据。
4. 分析前快照，分析后回滚。
5. 不运行你不理解的样本；先静态分析。

### 流程

1. **静态**：文件类型、哈希、字符串、导入表、节区、编译器、加壳。
2. **动态**：进程、文件、注册表、网络、API 调用。
3. **行为**：持久化、提权、横向、外联、加密。
4. **IOC**：哈希、域名、IP、注册表键、互斥体、YARA。
5. **报告**：样本信息、行为链、ATT&CK 映射、检测建议、处置建议。

### 工具

- PEStudio、CAPA、Detect It Easy、strings、FLOSS。
- Procmon、Process Explorer、Autoruns、TCPView。
- Wireshark、FakeNet-NG、INetSim。
- Volatility3（内存）、YARA。
- REMnux、FLARE VM。

## 十三、最后的提醒

- 二进制安全最容易让人产生"我很厉害"的幻觉。真正的能力不是"能弹 shell"，而是**能解释为什么、能稳定复现、能修复、能写清楚**。
- 不要收集 exploit 脚本。要收集**根因分析**和**修复方案**。
- 不要碰真实目标。所有练习都在本地/授权靶场。
- 如果你连续两周卡在同一个概念，换一个更小的例子，或者回到 C/汇编补基础；不要硬扛。
