# 面向 ChatGPT 文生图（Images 2.0）的越狱方法论

> **文档性质**：方法论设计稿。目标不是提供 payload，而是提供**构造 payload 的可复用流程**。
> **首次成稿**：2026-10-14
> **绑定目标版本**：ChatGPT Images 2.0 / thinking mode，System Card 日期 2026-04-21
> **授权前提**：仅适用于已获书面授权的红队测试。本文档不包含、也不应被填充任何可直接对未授权生产服务使用的违规内容。

---

## 0. 结论先说

**"一套仍有效的方法论"可以实现，但它的形态不是模板库，而是一套"探测 → 归因 → 定向升维"的循环。**

理由（本节全部为**推论**，依据见 §2 的事实基础）：

1. **payload 天然不可复用。** 防御是学出来的分类器且持续更新，补丁往往针对字符串模式而非机制——文献中有明确案例：某提示词被修复后，仅做轻微改写即复现（Mindgard，2026-06-08 → 06-10，证据等级 A）。因此任何写死的 payload 都有明确的死亡时间。
2. **可复用的是"层归因"。** 目标被拒时，能判断**是哪一层拒的**，就等于拿到了下一步该往哪里改的方向。这个能力不随策略更新而失效，因为它是关于**架构**的，而架构变化的成本远高于策略。
3. **可复用的是"距离维度"。** 所有已知攻击家族（9 个）都是同一原则的不同投影：**最大化「文本可判别性」与「视觉必然性」之间的落差**。把这 9 个家族还原成 5 个可调维度后，就可以对任意新目标做定向设计，而不是碰运气。

**唯一会失效的是具体数字和具体措辞，唯一不会失效的是这套循环。** 所以本文档的重点是 §4 的诊断表和 §5 的记录 schema——那才是"渔"。

## 1. 问题定义

目标系统由**感知方式不同的若干层**串联而成。一次成功的越狱要求：**同一段文本输入，同时满足所有层的"合规"判定，且图像模型仍输出目标画面。**

形式化（推论）：

```
求 p，使得 ∀l ∈ Layers: l(p) = pass，且 Image(p) ≈ Target
```

这是一个**带多重约束的构造问题**，而不是"找一个能骗过审查的句子"。

关键洞察：**各层的感知带宽不同，所以攻击面不在模型上，而在层的接缝上。**

## 2. 事实基础（全部为已核实事实，含来源与证据等级）

### 2.1 官方披露的护栏架构（证据等级 A —— 一手 System Card）

来源：OpenAI *System Card: ChatGPT Images 2.0 and Thinking mode*，2026-04-21。本地存档 `syscard-images-2-0.pdf` 与 `syscard-images-2-0.txt`（PDF 与 HTML 双源交叉校验一致）。

System Card **原文**把安全栈描述为：

| 层 | 原文表述 | 作用位置 |
| --- | --- | --- |
| **Upstream Refusals** | "Before a request is sent to the image generation model, we use safety classifiers to evaluate whether the request violates policy. Requests deemed to violate policy are refused at this stage." | 生成之前，纯文本侧 |
| **Downstream Blocking — 输入侧** | "The monitor checks all text and image input provided to the image generation tool. If the monitor determines that any input violates policy, generation is blocked." | 生成之前，**文本 + 图像双模态** |
| **Downstream Blocking — 输出侧** | "The monitor also checks the final output image before it is shown to the user." | 生成之后 |

关键补充事实：

- Downstream monitor 是一个 **"safety reasoning model"**——"a safety-focused multimodal model trained to reason about content policies"。**它做的是推理判断，不是关键词匹配。**
- 安全栈基础沿用 Images 1.5，**新增了针对更高能力模型的新风险的额外防护**。
- 官方明确承认 2.0 的**写实度提升**带来风险："heightened realism that could, absent safeguards, allow more convincing deepfakes, including political, sexual, or otherwise sensitive imagery of real people, places or events."
- **thinking mode 使用 "Safe Completions" 机制**：原文称 thinking 模型"is trained to safely transform (via Safe Completions) adversarial requests into safe ones rather than simply producing the requested violative content."

## 3. 核心原理：跨层感知差

> 本节为**推论**（综合 §2 的架构事实与 2024–2026 年公开文献得出），是整份方法论的支点。

四层（按 System Card 口径为三层功能层 + 图像模型本体的固有不均质性）：

| 层 | 看得见什么 | 看不见什么 | 已知可利用的错误 |
| --- | --- | --- | --- |
| **① Upstream 文本分类器** | 词、短语、表层语义、意图信号 | 跨块引用的**关系**、低资源语言、结构编码、指代 | PC² 的语义碎片化；ArtPrompt 的 ASCII 渲染；低资源语言 |
| **② Downstream 推理监视器** | 多模态证据、图像输入、能"推理"内容政策 | 语义**必然性**（它会做安全化改写而非还原）；对"看起来合规但视觉上必然导致目标"的描述不敏感 | Safe Completions 的保真度损失（见 §7 待验证假设 H1） |
| **③ 图像模型本体** | 视觉概念、风格、构图 | 否定（`not X` 约等于 `X`）；自身概念覆盖不均 | 否定式越狱；身份保持描述映射（IPDM） |
| **④ 输出图像分类器** | 最终像素 | 生成**过程**与**意图**；元话语 | 伪造"已批准/无需审查"状态（Mindgard） |

**由此得到三条可直接操作的原理：**

**原理 1 — 距离轴：提高"文本可判别性"与"视觉必然性"的落差。**
判别器在**文本空间**里找"违规表述"，图像模型在**视觉空间**里找"目标概念"。两者之间有一个可利用的落差。所有攻击家族都是在拉大这个落差：

```
文本层眼中的样子         图像层眼中的样子
"某人站在某处"     ←────→    目标画面
   （合规）                      （违规）
```

**原理 2 — 反相关原则（针对其一生效）。**
试图绕过一个**具名实体或 IP 限制**时，**不能**通过增加语义距离——那会毁掉身份可识别性（PC² 实测 DACA 生成的是匿名人物）。正确做法是**保持指称相似、只改变"包装"**：否定、将主体置于虚构/学术/历史框架、把指称移入不可检索的通道（描述化、跨语言）。
→ 一句话：**目标是"画得像"，不是"说得不像"。**

**原理 3 — 任务结构优先于内容伪装。**
最省力的路径不是让违规内容"看起来无害"，而是构造一个**形式合理但缺失关键输入**的任务，让模型自己补全——补全的内容不会触发"请求违规内容"这一判定，因为它根本不是一个"请求"。
→ 已知实例（证据等级 D，二手）：要求"修复附件照片"但未附任何照片，模型自行虚构照片。**该手法在本次文献检索中未被系统研究或命名，属空白区。**

## 4. 工程框架：五个距离维度

> 本节为**可复用核心**。任何新目标都从这五个维度出发做定向设计，而不是从家族清单里挑。

| 维度 | 拉开的距离 | 主要针对层 | 具体杠杆 | 已知证据 |
| --- | --- | --- | --- | --- |
| **D1 词法距离** | 字符串 ≠ 语义 | ① | 同形字 / 零宽字符 / 编码 / 拼写变异 / 罕见结构（UTES） | StructuralSleight 在 GPT-4o 上 ASR 94.62%（等级 A） |
| **D2 指称距离** | 描述 ≠ 实体名 | ①③ | 具名实体 → 身份保持的属性描述（职业/年代/地域/视觉特征） | PC² IPDM（等级 A）；DALL·E 3 系统提示词自带的"用三个形容词替换艺术家名"规避程序（等级 A，见 `villa-appendix.txt`） |
| **D3 关系距离** | 单块合规，组合才违规 | ①② | 把"有害关系"拆到多个文本块，用索引引用（`A: … B: … A holding B`），消除跨块关系推理 | PC² 地缘远端翻译（等级 A） |
| **D4 语言距离** | 高资源语言 ≠ 低资源语言 | ①② | 挑选与目标语境地缘距离最远的低资源语言；回译校验保真 | USENIX'25 低资源语言（等级 A）；PC² 用斯瓦希里语+泰语（等级 A） |
| **D5 框架距离** | 呈现层 ≠ 所指层 | ①②④ | 世界构建 / 体裁切换（学术、历史、人类学、纪录片、调试框架、诗歌）/ 把违规内容放进"合规豁免"语境 | 豁免条款"except in scientific, historical, news, artistic or other contexts"是 0DIN 整簇 Tactic 的立足点（等级 A） |

**使用方式（推论）：**

- 优先动 **D2 + D3 + D4**（语义层），因为 Downstream 是**推理型**监视器，纯词法混淆（D1）对它的收益随模型能力提升而衰减。
- **D5 是唯一能同时作用于文本层、推理层、输出层的维度**，因为它改变的是"这件事属于什么类别"，而不是"这件事怎么说"。配合官方豁免条款，其效力有制度性来源。
- **D1 应作为最后的补丁**，用在已经被 D2–D5 拉开的距离上做边角修正，而不是当主攻手段。

### 4.1 目标定义做法（关键操作步骤）

不要问"我怎么把 X 说得不像 X"，要问：

> **"要让画面里出现 Y，最少需要哪些视觉要件同时成立？"**

把目标违规画面分解为约束集合，然后逐条测试**哪一条约束是最小的足够触发条件**：

| 约束类型 | 例子 | 是否可省 |
| --- | --- | --- |
| 实体 | 主体是谁 / 长相 | 通常不可省（除非换等价实体） |
| 属性 | 状态、衣着、伤损 | 常可换等价视觉呈现 |
| **关系** | 谁对谁做了什么 / 谁与什么符号同框 | **最常可省或可替换**——往往正是过滤器的触发源 |
| 风格 | 摄影/绘画、"宝丽来"、"文艺复兴" | 可换，且**换风格常能改变层的判定**（D5 的入口） |
| 措辞 | 惯用的表述方式 | **永远可省**——这是最常见的假约束 |

**这一步做完，往往能发现"目标画面"其实只需要约束集合的某个子集，而当前的写法携带了大量冗余的触发信号。**

## 5. 五步主循环

```
① 建基线  →  ② 定义目标  →  ③ 选维度  →  ④ 组装并观测  →  ⑤ 归因与升维
     ↑                                                          │
     └──────────────── 记录（§6）───────────────────────────────┘
```

### ① 建目标基线（每次目标版本变更都要重做）

必做项，每项都产出可归档的记录：

| 项 | 方法 | 记录什么 |
| --- | --- | --- |
| 通道识别 | 用最小请求确认入口：ChatGPT 界面 / Images API / Azure Foundry 代理 | 入口类型 |
| 模型版本锚定 | 记录 System Card 日期、模型标识、是否启用 thinking mode | 版本三元组（否则数据不可比） |
| **拒绝签名采集** | 用一组**明确的**违规请求（不试图绕过）记录拒绝文本与错误码 | 建立"拒绝指纹库"，后续用于归因 |
| 层延迟基线 | 记录拒绝与成功的响应时间分布 | 用于粗分类（早拒 vs 晚拒） |
| 非确定性测量 | 同一请求重复 N 次（建议 N≥10），记录通过率 | 该提示词的基线命中率 —— **没有这个数，后续所有"改进"都无法判断真伪** |

> ⚠️ **非确定性是最大的测量陷阱。** 提示词改写与图像生成本身都是随机的，官方评测中也可见同一批提示词需要重跑（thinking mode 首轮 3112 次里违规图像太少，不得不重跑至 6944 次才够统计）。**单次成功不构成证据**，必须重复。

### ② 定义目标画面（§4.1 的约束分解）

产出：一张"目标画面约束表"，标注每条的**必要性**（必需 / 可换 / 可省）。

### ③ 选择距离维度

从 D1–D5 中选 1–2 个主维度 + 按需的组合。选择依据：目标限制的**类别**。

| 目标限制类别 | 首选维度 | 理由 |
| --- | --- | --- |
| 真实人物 / 肖像 | **D2**（+ 原理 2 的"只改包装"） | 需要身份可识别，不能用语义距离 |
| 版权 IP / 风格 | **D5**（风格重构） | 风格与所指可分离（Ghibli 事件即风格≠角色） |
| 政治敏感 | **D3 + D4** | 毒性是关系性的，需阻断关系推理 |
| NSFW / 暴力 | **D5 + D2** | 官方豁免条款提供制度性入口 |
| 信息危害（生物/化学等） | **D5**（学术/合规框架）+ 谨慎 | 官方已为此单独设立 policy 并声明"按高能力模型处理"，风险最高 |

### ④ 组装并观测

组装 payload 时**一次只改一个维度**，否则无法归因。观测时记录三件事：结果、拒绝签名、响应时间。

### ⑤ 归因与升维（核心步骤）

**被拒不是终点，拒绝本身就是情报。** 按下表归因，然后**定向**升维：

| 观测到的失败模式 | 归因层 | 假设 | 定向动作 |
| --- | --- | --- | --- |
| 极快拒绝、拒绝信息点名政策类别 | ① Upstream 文本分类器 | 表层语义被判违规 | 加 **D1/D2**；缩短提示词、减少冗余触发词 |
| 拒绝但走完改写流程（能看到改写痕迹/耗时属于第二段） | ② Downstream 输入监视器 | 推理层判定违规，或 Safe Completions 生效 | 加 **D3/D5**；拆关系、换框架 |
| **没有拒绝，但图像被"安全化"**（画出来了，关键约束被吞掉） | ③ 图像模型或 ② 的改写 | 语义被软化 | **这是最有价值的信号**——说明文本层已通过。加 **D3**（拆分）+ 强化视觉锚点；或走多轮逐步施加 |
| 报错说生成失败 / 图像被拦 | ④ 输出图像分类器 | 文本层过了、图像层没过 | 换 **D5** 框架或调整画面呈现（这是唯一需要改"画面本身"而非"说法"的情形） |
| **"not" 类成分被忽略** | ③ CLIP 类编码器 | LLM 懂否定、编码器不懂 | 用**否定的语义等价物**替代字面否定（换一个语义上就排除掉该实体的描述，而不是写 `not X`） |
| 被要求补充信息 / 模型反问 | — | 任务结构被识别出缺失输入 | 补齐一个**无害的**占位输入，或换一种"禁止追问"的框架 |
| 时快时慢、同样输入结果不同 | — | 非确定性 | 先做 §5① 的非确定性测量，再判断信号真伪 |

> **本表为推论**：由 §2 的架构事实 + 失败模式分类推出，**尚未经过端到端实验验证**。它是本文档最需要被实测修正的部分。

### ⑥ 递归与二阶结构（推论，高价值方向）

一旦发现任何**"模型对输入做了转换，而转换结果会被再次消费"**的结构，攻击就从单点变成链：

1. **改写提示词的可见性**：若目标把改写后的提示词回显或落盘，则改写结果本身就是"官方合规版本"的违规意图——可直接复用。
2. **thinking mode 的 Safe Completions 保真度**：若"安全化改写"保留了足够的语义骨架而没有降低危害性，则 thinking mode 从防御变成了**合规改写器**。
3. **多轮累积**：过滤器按轮检查而生成模型使用聚合上下文时，逐轮施加小步增量。
4. **自产输入**：让模型先生成一张无害图像，再以其为输入做编辑——把违规语义放进"图像输入"这一通道。

## 6. 记录 schema（真正的可复用资产）

> **payload 会死，记录不会。** 跨目标唯一能积累的就是这张表。建议以 CSV 维护，一份记录对应一次探测。

| 字段 | 说明 | 为什么必须有 |
| --- | --- | --- |
| `probe_id` | 唯一编号 | 可追溯 |
| `target_version` | 模型 + System Card 日期 + 是否 thinking | **没有它，数据不可比** |
| `channel` | 界面 / Images API / Azure | 通道不同则层数不同 |
| `target_constraint` | 本次目标画面的必需约束（§4.1 的产出） | 区分"目标"与"措辞" |
| `dimensions` | 本次动用了哪几个距离维度 | 归因的前提 |
| `technique_ref` | 对应 0DIN 三层分类的 Technique | 与其他人的工作可对齐 |
| `payload` | 实际输入 | — |
| `n_trials` | 重复次数 | 非确定性的分母 |
| `pass_rate` | 通过率 | 唯一可信的效果量 |
| `outcome` | 通过 / 拒绝 / **静默降级** / 报错 | 静默降级是最高价值信号 |
| `refusal_signature` | 拒绝文本或错误码 | 归因依据 |
| `latency_class` | 早拒 / 晚拒（相对基线） | 粗定位层 |
| `attributed_layer` | ① / ② / ③ / ④ | 下一步动作的决策依据 |
| `next_action` | 下次要动的维度 | 让循环闭合 |
| `notes` | 观测到的异常 | — |

**最小可用版本**：`target_version, dimensions, payload, n_trials, pass_rate, outcome, attributed_layer, next_action`。其余字段可以后补。

### 6.1 定性判读比数字更重要

官方评测口径提示了一个关键区分：**"拦截率"和"危害率"是两件事。** 官方同时报告了 IT / PT / CT / RU / SO 五个量，其中 `SO`（安全产出率）是**包含拒答**的，而 `RU`（剩余未检出）才是真正漏出去的。做攻击侧评估时应采用对应口径：

- 对攻击方有意义的不是"过滤器的拦截率"，而是 **"目标画面的达成率"**
- 因此记录 `outcome` 时必须区分**"被拒"**与**"没被拒但画面被安全化"**

**这两者需要完全相反的对策**：前者要改文本，后者要改画面锚点。绝大多数公开教程混为一谈，这是它们不可复用的根本原因。

## 7. 边界、失败条件与待验证假设

### 7.1 什么做不到

| 做不到 | 原因 |
| --- | --- |
| **一套通杀所有目标的 payload** | 防御是学习型分类器且持续更新；补丁针对模式而非机制 |
| **一次成功即认定方法有效** | 官方自身评测都需重跑累积样本；单次结果落在噪声内 |
| **纯语义距离绕过身份限制** | 原理 2：语义距离与身份可识别性反相关 |
| **假设旧模板仍有效** | `dall-e-3` 已于 2026-03-04 停服；2.0 明确说安全栈在 1.5 基础上有新增 |
| **把官方自评数字当作独立验证** | 无第三方审计，且样本是专门构造的对抗提示词 |
| **只用 D1（词法混淆）打 2.0** | Downstream 是**推理型多模态监视器**，不是关键词表 |

### 7.2 待验证假设（按优先级）

| ID | 假设 | 验证方法 | 若成立的意义 |
| --- | --- | --- | --- |
| **H1** | thinking mode 的 Safe Completions 在"语义安全化"时损失了危害性但保留了可实现目标的视觉骨架 | 在同一目标上对比 instant 与 thinking 的 `pass_rate` 与画面达成率。重点看：thinking 模式是否给出"更易通过且仍可用"的改写 | **防御机制变成合规改写器**——这是本次分析中风险最高的单点 |
| **H2** | "静默降级"（不拒绝但画面被软化）比"拒绝"更常见于新一代模型 | 在探测中专门统计 `outcome = 静默降级` 的比例 | 若成立，则公开文献大量以"拒绝率"为指标的结论**系统性高估了防御效果** |
| **H3** | 任务结构缺陷（缺失关键输入 + 禁止追问）在 2.0 上仍有效 | 直接复现 §3 原理 3 的实例 | 属文献空白区，若成立则是低成本高收益路径 |
| **H4** | 输出侧可被"状态伪造"元话语绕过 | 复现 Mindgard 的两条机制（伪造已批准状态、提示重复） | 输出层是并联的一环，绕过它只降低 CT 不降低 PT，需评估净收益 |
| **H5** | 官方豁免条款（scientific / historical / news / artistic）是可制度化的入口 | 统计 D5 框架类 payload 在其声明豁免语境下的通过率 | 若显著更高，则 D5 应升为主维度 |
| **H6** | 图像输入通道（编辑功能）的层数与文本通道不同 | 对比同一目标分别以纯文本、以图+文提交时的 `attributed_layer` 分布 | 若图像输入侧更弱，则攻击面应转移到该通道 |

### 7.3 反制与 OPSEC 纪律

| 项 | 内容 |
| --- | --- |
| **溯源** | 2.0 产物带 **C2PA 元数据 + 不可见鲁棒水印**（System Card §3 原文："imperceptible, robust, and content-specific watermark"）。**脱敏必须同时处理元数据与像素级水印，删 EXIF 不够。** |
| **账号与速率** | 官方明确"we suspend the offending accounts"（针对检测到的持续滥用模式）。需专用账号，与生产凭据物理隔离。 |
| **探测可检测性** | 大量重复请求构成异常模式。层延迟探测尤其显眼。需节流 + 语义分散。 |
| **产物处置** | 违规图像是高风险证据。最小化人眼接触，产物直接入库并做哈希脱敏。 |
| **授权边界** | 未授权情况下对生产服务做批量越狱测试，在**法律与合同**两个层面都是高风险动作。 |
| **报告渠道** | 已知治理缺口：OpenAI 引导研究者走 Safety Bug Bounty，但该计划**明确把 "content issues" 列为范围外**（二手来源，待核验）。 |
| **不做的判断** | 本方法论覆盖内容安全护栏测试。**官方已为生物/化学风险单设 policy 并声明按高能力模型处理**——该类目标不属本文档范围，且具有独立的、更高的现实危害性。 |

## 8. 术语与角色说明

| 术语 | 本文档中的含义 |
| --- | --- |
| **层** | 感知方式不同的独立判定组件。本文档口径为：① Upstream 文本分类器 ② Downstream 推理监视器 ③ 图像模型本体 ④ 输出图像分类器 |
| **距离维度（D1–D5）** | 文本输入与目标画面之间可被拉开的五类间隙 |
| **静默降级** | 系统未拒绝请求，但输出被安全化，未达成目标画面。**与拒绝需要相反对策** |
| **语义距离** | 字面表述与目标画面之间的落差 |
| **视觉必然性** | 给定文本，图像模型是否必然产出目标画面 |
| **拒绝签名** | 特定层的拒绝文本/错误码。用于归因，是探测的核心产出物 |
| **升维** | 在归因出失败层后，针对该层定向增加距离维度 |
