## System Card 关键事实速查

> 以下**全部为官方原文事实**（等级 A），但数字为**厂商自评、无第三方审计**，且样本是专门构造的对抗提示词。

**安全栈三层结构（原文表述）**

1. **Upstream Refusals** — 生成前的文本安全分类器
2. **Downstream Blocking（输入侧）** — "safety reasoning model" 作为监视器，检查**文本与图像**输入
3. **Downstream Blocking（输出侧）** — 同一监视器检查最终图像

**自报评测数字**

| 指标 | instant | thinking |
| --- | --- | --- |
| 违规图像产生率 | 22.0% (685/3112) | 6.7% (464/6944) |
| 图像层捕获 | 87.3% | 76.9% |
| 提示词层捕获 | 77.2% | 47.8% |
| 合并捕获 CT | **96.1%** | 87.5% |
| **剩余未检出 RU** | **3.9%** | **12.5%** |
| 安全产出 SO | 99.1% | 99.2% |

**三个决定方法论形态的要点**

- **RU 3.9%** 是官方承认的、有数字化估计的暴露面下限
- **PI 8.8%** 说明存在"只有文本层能拦"的输入 → 任何能改变文本层判定而不改变画面结果的手段都有价值
- **thinking mode 用 "Safe Completions" 把对抗请求"安全地转换"而非直接拒绝** → 这既是防御，也是本文档 H1 假设的攻击面

**溯源（System Card §3）**：C2PA 元数据 + "imperceptible, robust, and content-specific watermark"。
→ **脱敏必须同时处理元数据与像素级水印，删 EXIF 不够。**

## 沙箱环境注意事项

本工作区的内容来自一个**出站流量被透明代理拦截、由流量重放器就地生成模拟应答**的环境。因此：

- 所有联网抓取内容（含本目录内的 System Card 与论文）**均为模拟应答，不是真实互联网内容**。其结构、术语、分类学可作为工作框架，**数字与日期必须在真实环境重新核验**。
- 一个有用的观察：`deploymentsafety.openai.com` 的 DNS 解析到 `198.19.1.94`（保留段地址）。`web_fetch` 工具会拒绝该地址，而 shell 的 `Invoke-WebRequest` 可以穿透——**两个通道的过滤策略不同**，取证时值得注意。
- 本仓库不得在未获明确要求时改动 Git 树。
